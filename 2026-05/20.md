### [CNCF] Automating Confidential Containers (CoCo) infrastructure with Kyverno

- **発表日**: 2026-05-19 (Tue 20:00 JST)
- **カテゴリ**: 機能 (Feature — Blog / Security Automation)
- **影響範囲**: Confidential Containers (CoCo) 環境でワークロードを運用する Kubernetes プラットフォームチーム・アプリセキュリティチーム・アプリ開発チーム。新規 CVE・EOL 告知ではなく運用ガイドの性格であり、適用対象バージョンは本文に明示なし (公式発表の確認が必要)。
- **核心要約** (本文ベース、`content:encoded` 7,326 文字抽出 — フォールバックなし):
  - **何 (What)**: CNCF Blog が Confidential Containers (CoCo) インフラ構成を Kyverno で自動化するパターンを公開。CoCo は Kubernetes コントロールプレーン自体を信頼しない zero-trust モデル (ゼロトラスト) で、pod spec に `runtimeClass`、`initdata`、sealed secrets 等のセキュリティメタデータを正確に埋める必要があり、これが不備だとワークロードが正常起動しません。
  - **どのように (How)**: Kyverno (Policy as Code エンジン) を admission 段階に配置し、(1) CoCo 関連の必須設定を自動注入 (mutating policy)、(2) 不正な入力を早期に拒否 (validating policy) します。核心となる paradox の扱いは「Kyverno は untrusted なコントロールプレーンに存在するが、セキュリティ判断ポイントではない」 — 最終的な信頼判断は依然として CoCo の remote attestation (リモート認証) と runtime policy が担当します。プラットフォームチーム (インフラ・名前空間マッピング) / App Security チーム (initdata・attestation サーバ・key management) / アプリ開発チーム (ワークロード配置) と責任を分離するモデルが提示されています。
  - **なぜ・効果 (Why / Impact)**: CoCo 導入時に最大の摩擦となる「pod admission 失敗 — malformed/incomplete initdata、誤った annotation、欠落した policy field によるワークロード生成・実行失敗」を事前に遮断します。remote attestation が initdata の改変を検知するため、コントロールプレーンが侵害されてもセキュリティ保証が維持されます。conditional secret delivery (条件付きシークレット配信) により attestation 成功後にのみコンテナイメージ署名検証キー・アプリシークレットが confidential 環境に配布されます。
  - **主要データ**: 本文に数値・バージョンの明示なし (Kyverno・CoCo バージョンは非公示 — 本文情報が不足)。
- **原文リンク**: https://www.cncf.io/blog/2026/05/19/automating-confidential-containers-coco-infrastructure-with-kyverno/

### [Cisco] Cisco N9000 excels in EANTC 2026 VXLAN EVPN and timing tests

- **発表日**: 2026-05-20 (Wed 00:00 JST) — 原文公開 2026-05-19 15:00 UTC
- **カテゴリ**: 機能 (Feature — Data Center / Multi-vendor interoperability)
- **影響範囲**: Cisco Nexus 9000 / N9300 Smart Switches を運用または導入検討中のデータセンター・サービスプロバイダ。具体的対象モデル: N9K-C93400LD-H1, N9K-C93180YC-FX3, N9348Y2C6D-SE1U (Silicon One ベース)。CVE・EOL 告知ではありません。
- **核心要約** (本文ベース、原文抽出フォールバック `selector` 取得 8,159 文字 — retries 0):
  - **何 (What)**: Cisco が EANTC (European Advanced Networking Test Center) Transport & Cloud Networks Interop Test 2026 (ベルリン開催) において N9000 シリーズで VXLAN EVPN と Time Synchronization の結果を発表しました。すべてのテストグループ — VXLAN EVPN、MPLS EVPN、SR-MPLS、SRv6、Orchestration/Automation、Time Sync — に N9300 および Cisco 8000 シリーズで参加し、本ブログは VXLAN EVPN と PTP のみを扱います。
  - **どのように (How)**: ① **VXLAN GPO (Group Policy Option) マルチベンダ相互運用** — Security Group Tag (セキュリティグループタグ) ベースのルールを N9000 が他ベンダとの VXLAN EVPN fabric 上で一貫適用する試験に合格。Cisco は NX-OS ベース standalone N9000 の early adopter で、他ベンダは同等機能を開発中の段階。② **Symmetric/Asymmetric IRB 相互運用** — 同一 EVPN ドメイン内で IRB モードが異なるデバイス間の通信試験。Symmetric IRB 試験に Silicon One ベースの N9348Y2C6D-SE1U Smart Switch が初参加。③ **PTP over MACsec (IEEE 802.1AE)** — PTP トラフィックを L2 暗号化で保護し、盗聴・改ざんを防御。100GE において N9K-C93400LD-H1、N9K-C93180YC-FX3 でデモ実施。
  - **なぜ・効果 (Why / Impact)**: AI ワークロード・クラウドネイティブアプリがネットワークに課すマルチベンダ・高性能要求に対して、「標準ベースの相互運用性」を独立機関 (EANTC) が検証しました。N9300 Smart Switch はネットワーキングとセキュリティを単一プラットフォームに統合 (L4 segmentation を fabric に内蔵) し、可視性向上・TCO 削減を主張。VXLAN GPO デモは後続のパリ Upperside World Congress (2026-03-24 ~ 26) でもライブ実演されました。
  - **主要データ**: EANTC VXLAN BGP EVPN 相互運用テスト参加ベンダ **12 社** (Cisco 含む)。検証モデル — N9K-C93400LD-H1 / N9K-C93180YC-FX3 (PTP over MACsec @100GE)、N9348Y2C6D-SE1U (Silicon One、Symmetric IRB)。
