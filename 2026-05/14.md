## ⚠️ 収集失敗 — Claude in Chrome 接続失敗

`mcp__Claude_in_Chrome__list_connected_browsers` の応答が **接続ブラウザ 0件** でした。

Cowork の egress allowlist ポリシーにより `mcp__workspace__web_fetch` は対象4ドメイン (kubernetes.io, cncf.io, redhat.com, blogs.cisco.com) すべてが `cowork-egress-blocked` でブロックされるため、**Claude in Chrome MCP が唯一の収集経路** です。

### 現象
- `list_connected_browsers` のレスポンス: `[]` (空配列)
- RSS 4フィードの fetch を試行できず
- 韓国語 brief / 日本語ステージングともに生成不可

### 原因 (確定)
- Claude in Chrome 拡張機能がアクティブセッションにペアリングされていません
- スケジュール実行時点 (09:10 JST) で Chrome が起動していない、または拡張ペアリングが切断されています

### 影響範囲
- 2026-05-14 の日次ブリーフィング 1件 (韓国語・日本語ともに)
- 09:25 のタスクスケジューラ `DailyNews-JP-Push` は push 対象の新規日本語ファイルなし → no-op または前日ファイルの再 push (スケジューラ仕様に依存)

### 対応方針 (手動ペアリングが必要)
1. Chrome を起動し、**Claude in Chrome 拡張機能** のサイドパネルを開きます
2. 拡張機能側でペアリング要求を承認します (または Cowork セッション側から `switch_browser` をトリガー)
3. ペアリング確認後、本スケジュール (`daily-tech-brief`) を手動で再実行します
   - PowerShell: `Start-ScheduledTask -TaskName "daily-tech-brief"` (登録済みの場合)
   - もしくは Cowork から手動トリガー
