### [Kubernetes Blog] Kubernetes v1.36: Advancing Workload-Aware Scheduling

- **発表日**: 2026-05-13 (水 10:35 PST / 2026-05-14 03:35 JST)
- **カテゴリ**: リリース (Release) / 機能 (Feature)
- **影響範囲**: Kubernetes v1.36 新規リリース、`scheduling.k8s.io/v1alpha2` API グループ (v1alpha1 を完全置換)、kube-scheduler、Job コントローラー統合
- **核心要約** (本文ベース):
  - **何 (What)**: Workload-aware scheduling のアーキテクチャ進化 — Workload API (静的テンプレート) と新しい PodGroup API (ランタイム状態) を分離して導入しました。
  - **どのように (How)**: kube-scheduler に新しい **PodGroup scheduling cycle** を追加し、ワークロードのアトミック処理を実現します。v1.35 では Pod グループとランタイム状態が Workload リソース内に埋め込まれていましたが、v1.36 では Workload (static template) と PodGroup (runtime state) を分離します。PodGroup ごとの status シャーディングにより性能・スケーラビリティを改善し、ResourceClaim サポートにより PodGroup で Dynamic Resource Allocation (DRA) が利用可能になります。
  - **なぜ・効果 (Why / Impact)**: AI/ML・バッチワークロードにおける Pod 単位スケジューリングの限界を解消します。gang scheduling 用の `minCount` といったポリシーを宣言可能とし、topology-aware scheduling / workload-aware preemption への基盤を構築、Job コントローラーとの第一段階統合により実利用への準備が整いました。
  - **主要データ**: API バージョン `scheduling.k8s.io/v1alpha2` (v1alpha1 を完全置換)、サンプルポリシーで `gang.minCount: 4`。
- **原文リンク**: https://kubernetes.io/blog/2026/05/13/kubernetes-v1-36-advancing-workload-aware-scheduling/

### [CNCF] Building a cloud native platform from the ground up with Kairos, k0rdent, and bindy

- **発表日**: 2026-05-13 (水 11:30 UTC / 2026-05-14 20:30 JST)
- **カテゴリ**: 機能 (Feature) / その他 (Blog)
- **影響範囲**: 50以上の Kubernetes クラスター (オンプレミス VMware + マルチクラウド) を運用する規制業界 (金融) のプラットフォームエンジニア。RBC Capital Markets の事例に基づきます。
- **核心要約** (本文ベース):
  - **何 (What)**: GitOps (FluxCD) ベースのプラットフォームを拡張する中で直面した3大課題 (クラスターのライフサイクル管理 / ノードの再現性・tamper-evident なブート / エンタープライズ DNS と Kubernetes サービスディスカバリの統合) を解決するためのツール組み合わせを紹介します。
  - **どのように (How)**: **Kairos** (CNCF Sandbox) — ノードの不変性 (immutability) を提供する Linux ディストリビューションです。すべてのノードが OCI イメージから起動し、RHEL ベースに承認済みセキュリティ設定を焼き込み、cloud-config モデルで SSH 鍵・ネットワーク・SSSD (Active Directory)・Kubernetes エージェント登録を YAML で宣言します。**k0rdent**、**bindy** も併用し、CNCF 既存プロジェクトで不足する部分は自社開発しています。
  - **なぜ・効果 (Why / Impact)**: 単一の off-the-shelf ツールでは解決できなかった50以上のクラスター・ハイブリッドインフラ運用の課題を GitOps ワークフロー内で処理し、ネットワークチケットキューのような外部 audit trail への依存を排除します。
  - **主要データ**: 50以上のクラスター、オンプレミス VMware + マルチクラウド、RBC Capital Markets (規制金融環境)。
- **原文リンク**: https://www.cncf.io/blog/2026/05/13/building-a-cloud-native-platform-from-the-ground-up-with-kairos-k0rdent-and-bindy/
