### [Red Hat Blog] Fragnesia and friends: When page cache vulnerabilities keep coming back ※ 📌 Cutoff 直前リカバリ

- **発表日**: 2026-06-02 (火曜日 09:00 JST) / 原文表記 Tue, 02 Jun 2026 00:00 UTC
- **カテゴリ**: セキュリティ (Linux Kernel Vulnerability / Container Escape / OpenShift Defense-in-Depth)
- **影響範囲**: Linux カーネルを利用するすべてのワークロード — 特に **OpenShift コンテナ環境**。⚠️ **デフォルトではない SCC (例: `anyuid`) で UID 0 コンテナを運用する brownfield 環境ではリスクが上昇**
- **核心要約** (本文ベース):
  - **何 (What)**: 直近 2 週間で公開された Linux カーネル page cache 関連の **4 件の権限昇格 CVE シリーズ** に関する Red Hat OpenShift Security チームの分析レポート。CVE 引用:
    - **CVE-2026-31431 (Copy-Fail)** — page cache の一般的操作
    - **CVE-2026-31635 (DirtyDecrypt)** — rxgk 経路
    - **Dirty Frag** — ESP/XFRM、RxRPC 経路
    - **Fragnesia** — ESP-in-TCP
  - **どのように (How)**:
    - 本文の著者が OpenShift 上で直接 PoC を実施 — vanilla Fedora コンテナ (default SCC) では `user namespace creation` がブロックされ、**コンテナエスケープに失敗** (SCC + SELinux 効果)
    - `anyuid` SCC + UID 0 シナリオ (brownfield 環境でよくあるパターン) → **この組み合わせではエクスプロイト経路が有効化される可能性**
    - 同じ page cache の前提・安全装置欠如のパターンが、隣接するカーネルサブシステムでも繰り返し発見される構造的問題を指摘
  - **なぜ・効果 (Why / Impact)**: 個別 CVE のパッチではなく **defense-in-depth アーキテクチャ (SCC、SELinux、user namespace 制限)** のレジリエンスが鍵。14 日間に 4 件の CVE が登場するパターンは今後の亜種出現の可能性を示唆
  - **主要データ**:
    - 14 日間に 4 件の主要 Linux 権限昇格 CVE が登場
    - default OpenShift SCC + SELinux 組み合わせで PoC はすべてブロック (検証環境: ROSA クラスター)
- **運用影響 ⚠️**:
  - OpenShift 運用中の `anyuid` SCC + UID 0 コンテナ利用状況を即座に inventory
  - 可能であれば default SCC の強制、user namespace 利用制限の維持
  - カーネルパッチ適用スケジュールとは別に **SCC ポリシー強化** を第 1 防御線として
- **原文リンク**: https://www.redhat.com/en/blog/fragnesia-and-friends-when-page-cache-vulnerabilities-keep-coming-back
